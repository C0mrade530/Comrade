# Методологические основания

Это прикладная сборка методов для маленького продукта, не полный пересказ книг и не заявление об изучении всех названных авторов. Использованы публичные первичные материалы, проверенные 21 октября 2026 года. Детали API, доступности сервисов и тарифов требуют повторной проверки во время реализации.

## Уточнения, влияющие на решения

- MVP нужен для проверки конкретного предположения; не каждый дешёвый файл и не любое приложение автоматически полезны.
- Самое рискованное предположение бывает о проблеме, спросе, достижимости или экономике. RAT не сводится всегда к одному интервью-вопросу.
- Слова «купил бы», список ожидания, платёж и достигнутый результат дают разные сведения.
- «40% очень расстроятся» не универсальная сертификация PMF и не основание объявлять его по нескольким знакомым. На малом пилоте фиксируй реальные результаты, объём выборки и ограничения, не заявляя устойчивое соответствие рынку.
- LTV/CAC при корректном расчёте характеризуют экономику, а не доказывают решение боли. До наблюдений не придумывай эти показатели.
- Одноразовый гайд не обязан формировать привычку. Удержание и Hook-подход имеют смысл для естественно повторяющейся задачи.
- Продажа результата не означает обещание дохода или неконтролируемого внешнего эффекта. Убедительность оффера не заменяет полезность и доказательства.
- Полное решение выбранной задачи не равно закрытию всех потребностей человека. Связанные необходимостью материалы допустимы; несвязанные функции раздувают продукт.
- Практические вопросы продаж можно адаптировать из SPIN; для недорогого самостоятельного товара длинная диагностика не обязательна. Имена известных продавцов не служат доказательством эффективности нашего предложения.

Остальные упомянутые пользователем авторы — ориентиры для возможного углубления по запросу, а не набор обязательных «агентов знаменитостей». Не приписывай им цитаты, биографии, рекорды и универсальные правила без проверки. Не обещай «продажа неизбежна» и не вычисляй вероятность покупки из уравнения ценности.
